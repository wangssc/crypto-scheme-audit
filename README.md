# crypto-scheme-audit

《信息系统密码应用方案》的本地自检工具。读一份 `.docx`，按 **GB/T 39786-2021 第三级**
检查章节结构和指标覆盖，输出一份报告。

不联网、不上传、不统计。方案文件始终留在你自己机器上。

---

## 这个工具到底是个什么

**是个结构检查器，不是安全评估。**

写过密码应用方案、走过密评的人都知道那种返工：
技术设计其实没问题，但 5.3 的九个要素少了三个、指标对照表只有 38 行不是 41 行、
自评栏里写了「符合」本该写「设计满足」——这些都不难改，但都会被退回来。

这个工具就是找这些的。范围仅限于此。

## 它不做什么

请先看这一段，再看分数。

- **不判断方案安不安全。** 它检查的是文档结构完不完整。满分只代表"结构上没发现明显缺失"，
  不代表"这个系统是安全的"。这是两件完全不同的事。
- **不核实密码产品。** 方案里说某产品存在、有认证证书，工具一律采信，无法验证。
- **不读图片内容。** 架构图、截图、图片形式的表格，全都看不见。
  只存在于图片里的信息等于没检查。
- **不支持 PDF 和 .doc。** 只吃 `.docx`。扫描件不做 OCR，也不打算做。
- **不替代人工评审。** 跨章一致性（第 3 章列的每个需保护对象，第 5 章是不是都有对应设计？）
  需要理解语义，工具只能提示，提示不参与评分。

## 安装

```
pip install python-docx
```

只有一个依赖。Python 3.8 以上。

## 用法

```bash
python audit.py 方案.docx                    # 文本报告
python audit.py 方案.docx --markdown         # Markdown 报告
python audit.py 方案.docx --json             # 机器可读
python audit.py 方案.docx --markdown -o r.md # 写到文件
python audit.py 方案.docx --fail-on critical # CI 用：有 critical 就返回 1
```

退出码：

| 码 | 含义 |
|---|---|
| 0 | 没有 critical |
| 1 | 有 critical（仅在设置了 `--fail-on` 时） |
| 2 | 输入读不了（文件不存在 / 不是 docx / 加密） |

注意：`--fail-on` 默认是 `none`，所以直接跑总是返回 0。CI 里要显式写
`--fail-on critical`。

## 不想开命令行：双击版

Windows 上可以把本项目打成双击版：**双击 → 浏览器自动打开界面 → 把 .docx 拖进去**。
不用装 Python，不用开命令行，也不用在系统选文件框里翻目录。

**这个 13 MB 的二进制不放在仓库里**（不该往 git 里塞可执行文件）。自己打一份，一条命令：

```bash
pip install pyinstaller python-docx
pyinstaller CryptoSchemeAudit.spec --noconfirm
```

产物在 `dist\密码应用方案自检.exe`。

### 界面怎么用

1. 双击 exe，浏览器自动打开（`127.0.0.1:8788`，只监听本机，局域网里别的机器连不进来）
2. 把方案 .docx 拖进虚线框，或者点一下选文件
3. 出结果：分数 + 等级 + 三个计数 + 分级问题列表
4. 底部四个按钮：换一份 / 打开报告文件夹 / 另存为 HTML / 退出工具

拖进来的不是方案文档时显示「未评估」，**不会给 0 分**——0 分会让人以为文档很差，
实际是工具没认出来，这是两件事。

工具不联网：界面**不加载任何外部资源**（没有 CDN、网络字体、图标库），
**唯一发出的网络请求是发给 `127.0.0.1` 上它自己的那个服务**。断网时功能一样。

这条不用信我，可以自己核：拖一份方案进去，同时按 F12 打开 Network 面板，
所有请求的 Host 都应该只有 `127.0.0.1:8788`；或者对源码跑
`grep -c 'https\?://' ui/index.html`，结果应当是 0。

### 后台进程怎么退

exe 没有窗口，「退出工具」是正常退出方式。直接关掉浏览器标签页也行，
但服务会等连续 20 分钟没有页面连接才自己退（浏览器会节流后台标签页的定时器，
阈值设短会误杀切去开会的用户）。下次双击会认出已经在跑的那个，不会再起一个。

报告写在 exe 旁的 `自检报告\` 目录；那个位置不可写（比如放在 `Program Files`）时，
自动退到 `%LOCALAPPDATA%\CryptoSchemeAudit\自检报告`。

检查过程中的任何失败都在页面上写明原因，不会一闪而过。

### 命令行模式

给了文件路径就走一次性检查，不启服务：

```bash
密码应用方案自检.exe 方案.docx              # 出报告并打开浏览器
密码应用方案自检.exe 方案.docx --no-open    # 只出报告，不开浏览器、不弹窗
```

源码版同理：`python app.py` 起界面，`python app.py 方案.docx --no-open` 走一次性。

改界面的同学双击 `run-dev.cmd`：跑源码版，改完 `ui/index.html` 刷新浏览器就能看效果，
不用每次等打包。

### 拿到 exe 后怎么确认没被改过

| 项 | 值 |
|---|---|
| 文件名 | `密码应用方案自检.exe` |
| 大小 | 14,400,978 字节（13.73 MB） |
| SHA256 | `0993bf147b2eb407e95875369192fde7c56c33365c60e1ba0e79c26c948256a5` |

在 exe 所在目录开 cmd 或 PowerShell，跑：

```
certutil -hashfile "密码应用方案自检.exe" SHA256
```

对上那串 64 位十六进制即可。

**自己打出来对不上是正常的**：PyInstaller 打出的二进制跟**版本、Python 小版本、
路径**都有关，换台机器就不可能一样。上面这组数字的生成条件：
Python 3.12 + PyInstaller 6.22.3 + 仓库根目录打包。要对上就照这个来。

**为什么杀毒软件可能报毒**：exe 由 PyInstaller 打包，没有代码签名证书。
它的自解压启动方式和某些恶意打包器特征相似，误报很常见。
不信这个二进制就自己打 —— 源码全在仓库里。

## 检查项

### 结构 S-01 – S-06

八章结构按公司常用方案模板整理，与 GB/T 43207-2023 设计指南的章节划分一致，
具体条款请以标准原文为准：

```
1 背景          2 系统概述      3 需求分析      4 目标与原则
5 密码应用设计   6 安全管理      7 合规性分析    8 实施保障
```

再加上子节齐全性：2.1–2.5、3.1–3.3、5.1–5.5，5.3 下的 a)–i) 九要素，
以及密钥管理 a)–j) 十环节。

章节标题按「章号 + 固定名称」双条件匹配，所以 `一、背景`、`1. 项目背景`、
`第一章 背景` 都认。正文里顺口提一句"背景"不算数。

### 指标覆盖 C-01 – C-07

找方案里的指标对照表（技术 22 行 + 管理 19 行 = 41 行），检查：

- 表在不在（不在直接报 critical，**不猜**）
- 行数对不对
- 22 条技术指标缺了哪几条
- 19 条管理指标缺了哪几条
- 级别列跟标准的「应 / 宜 / 可」是否一致
- 标了「不适用」的有没有写理由（C-07）

管理 19 项按 GB/T 39786-2021 第三级原文 **8.5 ~ 8.8** 逐条核对，
**全部是「应」**。写成「宜」会被报出来。

> 一个容易抄错的地方：三级的管理要求是 **8.5~8.8**，不是 9.1~9.8。
> 9.x 是第四级的要求，不少模板从别处抄来贴在三级方案里，整张表从这里开始错。

**C-07 值得单独说**，因为它是唯一一条能反驳「我写了不涉及就完事了」的检查。

22 项技术指标里「应」只有 7 项，剩下 15 项是「宜」和「可」。最省事的写法是把这
15 项全填「不适用」，反正没人逐条追。但 GB/T 43206-2023 第 4 章 b) 写得很清楚：

> 方案评估意见中**未对「不适用」作出明确说明**的，「宜」的条款**一律纳入**测评范围。

所以写「不适用」不给理由不是省事，是把这一条从「可以不测」变成「必须测」。
方案作者以为自己在减负，实际在给自己加活。

判定：对照表的「说明」列空着、只写「无」或「—」、或者跟结论一模一样，都算没写；
正文里写「本项不适用」而同一段没有理由的，也算。

范围卡死在 **8.1 ~ 8.4**。管理 19 项全是「应」，标不适用本身就该单独报，不在这条里混着算。

误报控制比检出更优先：引用标准原文的段落不算；「本系统不涉及视频监控」这类
描述范围的话也不算——只有「本项 / 本条 / 该指标不适用」这种带指代的自评句，
才会被要求给理由。

### 表述 W-01 – W-02

查自评里的「符合」。方案阶段没有实施证据，"符合"是下早了的结论。
可以写的说法：设计满足 / 满足 / 依赖云商提供 / 待验证 / 部分满足 / 不适用。

以下四种**不会**被报，可以放心写：

| 写法 | 为什么不报 |
|---|---|
| 不符合 | 意思相反，是如实说明差距 |
| 整改后符合 | 有明确前置条件 |
| 符合性分析 | 名词，不是断言 |
| 符合 GB/T ×××× | 说的是遵循编写规范 |

后两条是在规格之外加的排除项。不加的话，一份正常方案会报出几十条假问题
（章节名"合规性分析"、正文里引用标准，全都会中招），
报告一旦全是噪音就没人看了。

### 格式 F-01 – F-04

不参与评分，只影响观感：表格列数不齐、手打标题没用 Word 标题样式、
条款号写成 `8.2b` 或 `8.2-B`（应为 `8.2 b)`）、占位符残留
（`TODO` / `XXX` / `待补充` / `【】`）。

## 评分

```
penalty = critical 20 分 / warn 6 分 / hint 0 分，累加
score   = round(100 × e^(−penalty / 90))
有 critical 时，上限 65 分
```

| 情况 | 得分 |
|---|---|
| 没问题 | 100 |
| 1 条 warn | 94 |
| 3 条 warn | 82 |
| 1 条 critical | 65（封顶） |

如果文档根本不像一份方案（八章命中少于 5 个），结果是 **`not assessed`**，
分数是 `null` 而不是 0。

这一点是故意的：「没法评估」和「评估结果很差」是两种不同结论，
不应该长得一样。

## 隐私

工具在本地读 `.docx`，只输出发现的问题。发现项里只有章节名、条款号、表格序号，
**不会摘录你文档里的任何句子**。有专门的测试盯着这条
（`test_report_contains_no_source_snippet`），因为这类性质最容易在重构时悄悄失效。

除了你用 `-o` 指定的报告文件，不写任何东西。
